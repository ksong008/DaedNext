# rb72

rb72 fixes Juicity UDP owner isolation and stream failure handling, and corrects
the AnyTLS authentication padding length to `00 1e` before its 30 padding bytes.
Juicity uses the official stream-packet path with a real target. Port zero is
rejected before owner allocation because the official v0.5.0 raw path forwards
to port zero and does not decrypt its first packet. Raw TransportPacketConn and
cross-destination full-cone associations remain unsupported. Node URL parameters
are unchanged.

## Validation

The unmodified official Juicity v0.5.0 server passed exact UDP payload, eight
concurrent sessions, restart/reconnect and complete owner/endpoint release tests.
Local tests passed: resident UDP 118, Juicity owner/plan 11, AnyTLS 14 and AnyTLS
CLI 1. DaedNext protocol fixtures and OpenWrt packaging contracts passed.

The 187 matrix passed all 39 cases: 117 TCP rows, 76 UDP rows, 24,320/24,320 UDP
packets, 4,992 TCP smoke exchanges, and 39 successful cleanup checks. Compared
with the historical rb71 final run, TCP geometric means changed by -2.08% for
throughput, +2.41% for CPU ticks/GiB and -3.13% for peak RSS. This single historical
comparison does not establish a performance improvement. A short VLESS random
1-RTT UDP batch was an outlier; its separate repeat passed without loss but still
showed timing variance. Original full-matrix measurements were retained.

All 18 packages were unpacked and checked against the binary, geodata and web
input hashes. The v3 RPM was installed on Fedora 43 and the v3 APK on OpenWrt
25.12.4. Version, service, configuration, web and external connectivity checks
passed. Fedora retained its running proxy; OpenWrt retained its previously
disabled proxy state. ARM64 received ELF/package inspection, not a native device
runtime test. Configuration backups and rb71 rollback packages were retained
locally; build caches and remote installation/test remnants were removed.
